Phoenix RISC OS

A 64-bit RISC OS kernel, and what we learned building it

Phoenix is a bare-metal AArch64 RISC-OS-compatible kernel for the Raspberry Pi 4, CM4, Pi 5 and CM5. The source is not public yet. This is everything else: the hazards we hit porting to 64-bit, and a map of how the kernel is put together.

Porting to 64-bit RISC OS: what actually bites

Sentinels that sign-extend, flags that never reach a C caller, struct padding that moves every field, alignment checking nobody had ever switched on, relocations that come back eight bytes high. Plus the debugging habits that surfaced them. For anyone using the riscos64 toolchain, not only for Phoenix. Updated 14 September — switching the alignment check on found three real bugs, one of them in the relocation stub every riscos64 binary carries.

The one-paragraph version

The 64-bit bugs that hurt are not the ones that fail to compile. They are the ones where a 32-bit convention changes meaning rather than changing syntax — so the code still builds, still links, still loads, and then quietly reads a register nobody wrote or a field four bytes past where it lives. A 32-bit assumption on a 64-bit build goes silent; it does not go loud.

Corrections wanted

Bulletin No. 1 contains two entries that contradict things this project itself wrote earlier, and a third claim was caught and fixed on the day it was published. That is the process working, not failing.

If something here is wrong — or right but out of date — please open an issue. A correction is worth more to us than a compliment, and an issue beats an email because everyone else sees it too.

Open questions

Some problems are bigger than one project. Issues tagged open-question are things we have not solved and do not think we should solve privately, because whoever answers first effectively sets a convention for everybody.

The current one: how should a Wimp library represent a fixed 32-bit OS block in C at LP64? It blocks work in at least three codebases, and it has been found independently from both the 32-bit and 64-bit sides. If you have already solved it, that is the most useful possible reply.
